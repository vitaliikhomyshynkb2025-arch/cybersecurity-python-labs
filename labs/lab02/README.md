## Завдання 1

- `User`: профіль, `email` через property, приватні хеш і сіль.
  PBKDF2-HMAC-SHA256: 600 000 ітерацій, нова сіль 16 байтів через `os.urandom()`;
  порівняння через `hmac.compare_digest()`. Пароль не друкується і не журналюється.
- `Admin(User)`: наслідування, `super()`, незалежна множина дозволів.
- `Session`: UTC із часовим поясом, IP, `touch()` і таймаут.
- `AuditEntry`: незмінний dataclass; `AuditLog`: список подій і їх показ.
- `UserAccount`: композиція, вхід/вихід, перевірка сесії та інтерфейс ключів.

Email: локальна частина починається з латинської літери та має 3–64 символи
з літер, цифр або `_`; домен має принаймні одну крапку. Перевірка спрощена,
відповідає умові та не підтверджує існування поштової скриньки.

Сесія чинна, коли профіль активний та від останньої активності минуло
**менше 900 секунд**. Перевірка `is_authenticated()` не викликає `touch()`.
Невдалий повторний вхід очищує попередню сесію. Заміна користувача через ключ
також очищує її. Доступні ключі: `user`, `session`, `audit_log`; невідомі —
`KeyError`, неправильний тип — `TypeError`. Цей інтерфейс призначено для
композиції об'єктів у довіреному коді програми.

Демонстрація моделює таймаут зсувом `last_activity` на 900 секунд,
а не очікуванням 15 хвилин. Час записів аудиту справжній, тому змінюється
при запуску. Імпорт модулів не виконує демонстрацію.

## Завдання 2 та параметри CLI

| Параметр | Призначення | Типове значення |
|---|---|---|
| `--dns-log` | Вхідний CSV | `data/data_v08/dns_queries.csv` поряд із модулем |
| `--blacklist` | Текстовий чорний список | `data/data_v08/blacklist.txt` |
| `--out-csv` | Вихідний CSV | `data/data_v08/dns_alerts.csv` |
| `--min-domain-len` | Мінімальна довжина мітки для LONG_LABEL | `30` |

Методичка не задає числового порога або переліку TLD, тому прийнято
явну навчальну політику: поріг 30 символів для окремої мітки перед крапкою,
список TLD `.top`, `.zip`, `.xyz`. Поріг включний: 30 уже позначається.
Назва CLI з методички збережена; поріг стосується мітки, а не довжини всього FQDN.

Причини позначення:

- `BLACKLIST`: точний домен або його піддомен є у списку; межа крапки
  не дозволяє сплутати `notbad.example.org` із `bad.example.org`.
- `LONG_LABEL`: регулярний вираз знаходить довгу мітку.
- `SUSPICIOUS_TLD`: регулярний вираз знаходить TLD із навчального переліку.
- `DNS_LENGTH_LIMIT`: мітка довша за 63 символи або FQDN довший за 253.
  Такі записи архіву зберігаються як аномалії, а не мовчки відкидаються.

Це евристичні ознаки потенційних DGA-доменів або DNS-тунелювання.
Висока ентропія не обчислюється; факт компрометації не встановлюється.
Навіть легальний домен може відповідати евристиці. Мережеві запити й
автоматичне блокування не виконуються.

Статистика `Counter` рахує всі коректні запити, включно зі звичайними.
Домени приводяться до нижнього регістру, одна кінцева крапка прибирається.
CSV результату має п'ять колонок: вихідні чотири та `Reasons`.
Кілька причин розділяються `;` в одному рядку; транзакції не дублюються.

На наданому архіві: 13 коректних записів, 0 пропущено; A — 7,
AAAA — 2, TXT — 3, MX — 1; **7 підозрілих запитів**.
Причини: BLACKLIST — 3, LONG_LABEL — 4, SUSPICIOUS_TLD — 3,
DNS_LENGTH_LIMIT — 1. Їх сума 11, оскільки причини можуть перетинатися.

## Помилки та коди завершення

- `0`: команда завершена, результат збережено; наявність аномалій не є збоєм.
- `1`: відсутній файл, немає прав, неправильний заголовок/порожній журнал,
  пошкоджені дані або помилка експорту. Показується короткий ERROR без traceback.
- `2`: argparse відхилив команду або параметр, наприклад поріг 0 чи текст.

Неправильні окремі рядки пропускаються з WARNING та лічильником.
Якщо жодного коректного рядка немає, експорт не виконується.
Вихідний шлях не може замінити джерело, навіть через посилання.
Результат спершу пишеться в тимчасовий файл і замінює попередній після
успішного запису. Порожній перелік аномалій створює CSV лише із заголовком.
