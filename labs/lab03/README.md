Один запис — навчальне вимірювання часу відновлення. Категорії: `database`,

а не як максимально допустиме значення. Статус описує перевірку запису.

## Встановлення і запуск

З кореня того самого репозиторію, що й у попередніх роботах:

```sh
# Лише якщо наявного середовища немає: Python 3.10 або новіший.
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m labs.lab03.database
python -m labs.lab03.seed
uvicorn labs.lab03.main:app --reload --host 127.0.0.1 --port 8000
```

Перевірено з Python 3.12.14, FastAPI 0.143.1, Pydantic 2.14.1,
Uvicorn 0.54.0, Starlette 1.8.0, Ruff 0.16.8. Повні перевірені версії
залежностей зафіксовано в кореневому `requirements.txt`.

- Swagger UI: http://127.0.0.1:8000/docs
- OpenAPI JSON: http://127.0.0.1:8000/openapi.json
- Перевірка доступності: http://127.0.0.1:8000/ping

У звичайному запуску використовується `labs/lab03/data/lab3.sqlite3`,
визначений відносно файла модуля. За потреби окремої навчальної бази
можна передати `LAB03_DB_PATH`; ту саму змінну задайте для seed і Uvicorn.
Приклад без видалення або перезапису наявного файла:

```sh
export LAB03_DB_PATH="$PWD/labs/lab03/data/defense.sqlite3"
python -m labs.lab03.seed
uvicorn labs.lab03.main:app --host 127.0.0.1 --port 8000
```

Повторний seed непорожньої бази лише показує повідомлення. Застосунок
через lifespan створює відсутні таблиці, але сам не додає навчальні записи.
Початковий JSON, SQL і код є в Git; робочі бази й журнали перевірок ігноруються.

## Запити для показу

```sh
curl -i http://127.0.0.1:8000/ping
curl -i http://127.0.0.1:8000/student
curl -i http://127.0.0.1:8000/categories
curl -i 'http://127.0.0.1:8000/records?min_value=60'
curl -i 'http://127.0.0.1:8000/records?category_id=1&status=new'
curl -i 'http://127.0.0.1:8000/records?limit=2&offset=2'
```

Поріг включає рівність: повертаються V08-01, V08-04, V08-06, V08-08.
Поєднаний фільтр категорії 1 і статусу new повертає id 1 і 4;
сторінка limit=2/offset=2 — id 3 і 4. Усі результати впорядковано за id.

```sh
curl -i -X POST http://127.0.0.1:8000/records \
  -H 'Content-Type: application/json' \
  --data-binary '{"code":"V08-DEMO","title":"Демонстрація відновлення","category_id":1,"value":70.0,"status":"new"}'
```

Скопіюйте `id` з відповіді 201 для GET, PUT і DELETE `/records/{id}`.
PUT потребує всіх п'яти полів: code, title, category_id, value, status.
Поле id у POST/PUT та будь-яке невідоме поле відхиляються кодом 422.
Відповіді читання містять також category_name, отримане через JOIN.

```sh
curl -i -X POST http://127.0.0.1:8000/records/bulk \
  -H 'Content-Type: application/json' \
  --data-binary '[{"code":"V08-ROLLBACK","title":"Перший новий запис","category_id":1,"value":5.0,"status":"new"},{"code":"V08-01","title":"Дублікат наявного коду","category_id":2,"value":7.0,"status":"done"}]'
```

Очікується 409. Порівняйте всі записи до й після запиту через
`GET /records?limit=100`: їх кількість однакова, V08-ROLLBACK відсутній.
Якщо у другого елемента замість дубліката задати category_id=999,
результат — 404 і такий самий повний відкат.

## Фільтри та обмеження

- category_id: додатне ціле; відсутня категорія у фільтрі дає порожній список.
- status: new, in_progress або done.
- min_value: скінченне невід'ємне число, порівняння value >= min_value.
- q: буквальний підрядок у title, 1–120 символів, із урахуванням регістру.
  SQL використовує instr(title, ?) > 0; % та _ не є шаблонами.
- limit: 1–100, типово 20; offset: від 0, типово 0.
- Декілька фільтрів об'єднуються через AND.
- Назва категорії: 2–40 символів; code: 3–40; title: 3–120.
  Перед перевіркою моделі обрізають крайні пробіли.
- Ідентифікатори в JSON мають бути цілими числами; bool і дроби відхиляються.
- value приймає JSON-число, включно з цілим записом часу; bool, рядки,
  NaN та нескінченності відхиляються. Числова верхня межа відповідає
  готовому SQL і відкидає нескінченність, а не обмежує час порогом 60.
- Пакет: 1–100 повністю перевірених об'єктів; спільна транзакція без
  проміжних commit. Передчасна помилка скасовує попередні вставлення.

## HTTP-помилки

200 — читання/оновлення; 201 — створення; 204 — видалення з порожнім тілом.
404 — відсутній ресурс або категорія для вставлення; 409 — унікальність
або видалення непорожньої категорії; 422 — помилка моделі/параметрів.
500 — технічна помилка SQLite: подробиці лише в серверному logging.
Обробник валідації повертає loc/msg/type без копіювання небезпечних значень
на зразок NaN у JSON-відповідь.

Параметри SQL передаються через ?, з'єднання відкривається на одну
операцію і гарантовано закривається. with connection робить commit/rollback,
а closing(connection) закриває ресурс. BEGIN IMMEDIATE включає перевірку
посилань та запис у ту саму транзакцію. PRAGMA foreign_keys=ON виконується
для кожного з'єднання, а ON DELETE RESTRICT захищає категорії з записами.

## Повна відтворювана перевірка

```sh
python -m labs.lab03.verify
python -m unittest discover -v
python -m ruff check .
python -m ruff format --check .
```

verify потребує curl. Він створює окрему тимчасову базу, двічі запускає
seed, запускає Uvicorn на вільному локальному порту та виконує всі
14 сценаріїв методички через справжні HTTP-запити curl. Для останнього
сценарію процес Uvicorn справді зупиняється й запускається знову з тим
самим файлом бази. Демонстраційна база не змінюється. Тимчасові процеси
завершуються навіть після помилки перевірки.

Докази зберігаються локально у data/verification.json, verification.txt
(повні команди та відповіді) і verification.server.log. Альтернативний шлях:
`python -m labs.lab03.verify --output /повний/шлях/verification.json`.
