## Запуск на macOS

Відкрийте термінал у папці `cybersecurity-python-labs`.

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m labs.lab01.main --seed 8
```

Якщо середовище вже створене, достатньо активації та останньої команди.
Без `--seed 8` індекси трьох дублікатів обираються заново випадково.
Фіксований seed потрібен для відтворення результатів у звіті.
Запускати з кореня репозиторію; `python labs/lab01/main.py` не використовувати.

```sh
ruff check .
ruff format --check .
python -m unittest discover -v
```

## Узгоджене трактування методички

1. Завдання 1: min_length=10; завдання 3: min_length=11.
2. Спеціальний символ — символ із `string.punctuation`, не пробіл.
3. Усі обов'язкові групи: цифри, великі літери, спеціальні символи.
   Малі літери враховуються для розмежування слабких/середніх паролів,
   але не є додатковою обов'язковою умовою, якої немає у criteria.
4. Якщо виконано не всі обов'язкові критерії: 0–1 група символів —
   слабкий, 2 або більше — середній. Заборона й коротка довжина мають пріоритет.
5. Довгий складний повторний пароль — сильний, але не дуже сильний.
   Цей випадок у методичці явно не визначено.
6. Унікальність перевіряється в остаточному списку, включно з дублікатами.
7. У завданні 2 role і department збережено, але заданий алгоритм
   ухвалює рішення за active, blocked_users та clearance.
8. CSV без заголовка: рівно 10 рядків формату логін,хеш.
   Журнал — один коректний JSON-масив подій, а не склеєні JSON-об'єкти.
9. `args` і `kwargs` у журналі порожні навмисно: паролі не логуються.

## Межі навчальної реалізації

SHA-256(password + "00008") реалізовано точно за завданням.
Спільна передбачувана сіль і швидкий SHA-256 не є схемою зберігання
паролів для реального сервісу. Там потрібні випадкова унікальна сіль
на користувача та спеціальна повільна функція, наприклад scrypt.
Дані тестових паролів у коді вигадані для лабораторної.
Реалізація файлів розрахована на один процес і не є серверною БД.

`.venv`, папки `data`/`Data` на будь-якому рівні, кеші й секрети
виключені з Git. Правило `[Dd]ata/` охоплює також `log.tmp`.

## Усунення повторення коду

- `task1.run` оцінює кожен унікальний пароль один раз, а результат
  повторно використовує для його дублікатів. Усі 13 рядків збережено.
- `create_user` є спільним шляхом перевірки логіна і формування хешу
  для реєстрації та входу. `login` викликає цю функцію, не дублюючи
  перевірки. Сам виклик `create_user` не записує користувача в CSV.
- Перевірка пароля й солі залишається в `generate_hash`.
- Параметри заголовка третього завдання беруться з констант варіанта.
